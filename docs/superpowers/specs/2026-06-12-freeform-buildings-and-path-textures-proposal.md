# Предложение: свободные футпринты зданий + текстуры дорожек

Дата: 2026-06-12
Статус: **черновик на обсуждение** (вопросы к владельцу — внизу)

## Зачем

1. Здания не должны быть только прямоугольными и не должны вставать строго вплотную друг к другу.
2. У дорожек должна быть настоящая текстура и карта нормалей, а не тинт поверх тайла грядки.
3. Общий полишинг систем размещения.

## Что обнаружено в текущем коде

| Факт | Следствие |
|---|---|
| Здания (`PlacementLevel.Chunk`) занимают целые чанки и помечают `Occupied` **все** клетки чанка (`PlacementService.MarkChunkSubCellsOccupied`) | Здания прямоугольны, прилипают к сетке чанков, встают вплотную; рядом со стеной нельзя ни сажать, ни класть дорожку |
| Поворот (`RotationY`) вращает только префаб | Футпринт не вращается — повёрнутое 2×1 здание занимает те же чанки, что и неповёрнутое |
| Декор (`PlacementLevel.Cell`) не может пересекать границу чанка (`cx >= res → return false`) | Искусственное ограничение размещения |
| `BulldozeTool.TryRemovePlacedObject` ищет здание по дистанции до центра (3 м) | С нерегулярными футпринтами будет промахиваться |
| В `GroundInstanced.shader` дорожки = тайл грядки × тинт; `neighborFlags` (uv.w) считаются и передаются, но **во фрагменте не используются**; `_EdgeSoftness`/`_CornerRadius` объявлены и не используются | Заготовка под красивые кромки дорожек уже наполовину есть |
| UV тайла = 0..1 на клетку | Текстура дорожки будет видимо повторяться клетка-в-клетку |

## Предложение A: единое поклеточное размещение с маской футпринта

Отказаться от «чанкового» уровня размещения. Все placeable размещаются по клеткам (8×8 на чанк) с **маской футпринта**.

1. **`PlaceableData.Footprint`** — маска в инспекторе строками:
   ```
   FootprintRows = ["XX.", "XXX", "XX."]   // 'X' — занято, '.' — свободно
   ```
   Пусто → прямоугольник из `GridSize` (обратная совместимость).
2. **Размещение в любую клетку**, включая пересечение границ чанков: вместо локальной индексной математики каждый офсет клетки конвертируется через `ChunkSystem.WorldToCell` (заодно чинит баг декора).
3. **`Occupied` только по клеткам маски** → трава/посевы/дорожки подходят прямо к стенам; `_occupiedChunks` удаляется.
4. **Поворот Step90 вращает маску** (поворот bool-матрицы); превью футпринта показывает повёрнутую маску.
5. **Зазор между зданиями:** опциональный `PaddingCells` в `PlaceableData` — при проверке валидности маска расширяется на N клеток, но padding-клетки НЕ помечаются занятыми. Два здания с padding=1 гарантированно имеют зазор ≥1 клетку. По умолчанию 0 (вплотную можно, но не обязательно — позиция теперь свободная поклеточная, а не чанковая).
6. **Превью футпринта** — вместо одного квада подсвечиваются клетки маски (зелёные/красные по каждой клетке отдельно: видно, ЧЕМ именно мешает место). Рендер уже есть — `BrushPreviewService` инстансит квады.
7. **Bulldoze по зданиям** — попадание определяется по клеткам футпринта (cell lookup → PlacedObject), а не по дистанции до центра.
8. **Сейв** совместим: `PlacedObject` уже хранит chunkCoord+cell+rotation; футпринт восстанавливается из данных. Старые сейвы с чанковыми зданиями мигрируются (позиция чанка → его угловая клетка).

Альтернатива (минимальный вариант): оставить чанковый уровень, но добавить маску в чанках. Не рекомендую — не решает «вплотную», не даёт свободы позиционирования, и две системы размещения останутся навсегда.

## Предложение B: текстуры и нормали дорожек

1. **`Texture2DArray` вместо атласа**: `_GroundAlbedoArray` и `_GroundNormalArray` по слайсу на `GroundState` (grass, tilled, watered, fertilized, pathStone, pathWood, pathBrick). Массив вместо атласа → нет bleeding на мипах, тривиальный мировой тайлинг. (Старый 2×2 атлас уходит; материал собирается один раз редакторским скриптом из существующих текстур + новых текстур дорожек.)
2. **Мировая проекция UV для дорожек**: `uv = worldPos.xz / _PathTileSize` — дорожка выглядит непрерывной, без шва клетка-в-клетку. Для травы/грядок можно оставить локальный UV клетки (как сейчас).
3. **Нормали**: земля — плоский XZ-квад, TBN тривиален (T=(1,0,0), B=(0,0,1), N=(0,1,0)). Перенос освещения: NdotL с возмущённой нормалью + дешёвый Blinn-Phong спекуляр для камня/кирпича. Остаётся одним кастомным шейдером, mobile-friendly.
4. **Кромки дорожек** — доделать заготовку: `neighborFlags` уже считаются (`UpdateGroundNeighborFlags`); во фрагменте по флагам соседей скруглять углы (`_CornerRadius`) и смягчать кромку (`_EdgeSoftness`) — дорожка перестаёт быть жёсткими квадратами, на углах появляются скругления.
5. Тинты `_TintPath*` остаются как множители (и продолжают питать превью кисти).

## Полишинг (кандидаты, по убыванию ценности)

1. Поклеточная валидность в превью футпринта (из A.6) — игрок видит, какая именно клетка мешает.
2. Кромки/скругления дорожек (из B.4).
3. Bulldoze по футпринту (из A.7).
4. Снос деревьев — сейчас невозможен в принципе (ничего не зовёт `TreePlacementService.Remove`, у визуала нет коллайдеров). Включить сюда или отдельной задачей?
5. Пунктирный контур и на кисти дорожек, когда мазок за зданием (сейчас квады в слое превью — уже попадают в маску фичи; проверить и затюнить).
6. Цветовой пикер для краски (DyeTool.SelectColor уже готов, нет UI).

## Вопросы к владельцу (нужны ответы до спеки)

1. **Снап зданий**: остаёмся на клеточном снапе (позиция кратна клетке, 0.5 м при чанке 4 м / 8 клеток) или полностью свободное размещение без сетки? Рекомендую клеточный снап — сохраняет всю клеточную механику (occupancy, посадки, дорожки) без дробной математики.
2. **Зазор**: padding по умолчанию 0 (можно вплотную, но не обязательно) или глобально ≥1 клетка между зданиями?
3. **Маска строками в инспекторе** ("XX./XXX") — достаточно, или нужен визуальный редактор футпринта (дороже)?
4. **Текстуры дорожек**: есть готовые (albedo+normal)? Если нет — беру CC0-плейсхолдеры (например, с ambientCG) или генерим простые процедурные?
5. **Миграция сейвов**: старые сейвы с чанковыми зданиями конвертируем (предлагаю да) или ломаем сейвы (прототип же)?
6. **Снос деревьев** — в этот этап или отдельно?

## Вне объёма (предлагаю)

- Дороги со сплайнами/мешами (остаёмся на клеточной покраске).
- Свободное (без сетки) размещение зданий — если не выберешь иное в вопросе 1.
- Автотайлинг переходов дорожка-дорожка разных типов.
