# Свободные футпринты зданий + текстуры дорожек

Дата: 2026-06-12
Статус: согласован по вопросам предложения (`2026-06-12-freeform-buildings-and-path-textures-proposal.md`)

## Решения владельца

| Вопрос | Решение |
|---|---|
| Снап зданий | Клеточный (позиция кратна клетке, 8×8 клеток на чанк) |
| Зазор между зданиями | `PaddingCells`, по умолчанию 0 |
| Редактор маски | Нужен визуальный (сетка чекбоксов в инспекторе), хранение — строками |
| Текстуры дорожек | Готовых нет — генерируем процедурные плейсхолдеры |
| Миграция сейвов | Не нужна, сейвы ломаем |
| Снос деревьев | Вне объёма, отдельная задача |

Дополнение от 2026-06-12 (второй раунд ответов): в объём добавлены снос деревьев (бульдозером, возврат 50%), пикер цвета краски, мягкий бленд на стыках типов дорожек, и Free5-поворот теперь вращает футпринт (конservативная растеризация).

Реализация — **три этапа** (отдельные планы): A — размещение (+деревья, +Free5), B — рендер земли (+бленд стыков), C — пикер краски (маленький). Планы A, B, C независимы друг от друга; внутри A шаг «снос деревьев» (A4b) идёт строго после ядра A3 (ему нужны `TryGetAt` и удаление `PlacementLevel`).

---

## Часть A: поклеточное размещение с маской футпринта

### A1. Данные (`PlaceableData`)

- Удаляется `PlacementLevel` (и весь чанковый уровень размещения). Все placeable — поклеточные.
- Новое поле:
  ```csharp
  [Tooltip("Маска футпринта. 'X' — занято, '.' — свободно. Пусто = прямоугольник GridSize.")]
  public string[] FootprintRows;   // например ["XX.", "XXX", "XX."]
  public int PaddingCells = 0;     // зазор для проверки валидности (клетки вокруг маски)
  ```
- `GridSize` остаётся как fallback (пустая маска → сплошной прямоугольник `GridSize.x × GridSize.y` **в клетках**, не в чанках).
- Рантайм-обёртка `FootprintMask` (в `WheatFarm.Core.Data`): парсит строки в `bool[,]`, кэширует 4 поворота (Step90), отдаёт `IEnumerable<Vector2Int> Cells(int rotationSteps)` и `BoundsInt`. Невалидные символы/рваные строки → ошибка в консоль + fallback на GridSize.

### A2. Визуальный редактор маски

- `PropertyDrawer` для футпринта в `Assets/Scripts/Editor` (asmdef `WheatFarm.Editor`): сетка тогглов (клик переключает клетку), кнопки +/− строк и столбцов, кнопка «из GridSize». Хранение остаётся строками (`FootprintRows`) — диффится в git, правится руками при желании.

### A3. `PlacementService`

- `_occupiedChunks`, `CanPlaceChunkLevel/PlaceChunkLevel/FreeChunkLevel/MarkChunkSubCellsOccupied`, `ChunkFootprintCenter` — удаляются.
- Единый путь: якорная клетка = `WorldToCell(worldPos)`; для каждого офсета маски (с учётом поворота) клетка вычисляется через мировые координаты (`CellToWorld(якорь) + офсет·CellWorldSize → WorldToCell`) — **пересечение границ чанков работает** (чинит и старый баг декора).
- `CanPlace`: каждая клетка маски — `chunk != null && Unlocked && !Occupied && !HasPlant`; плюс клетки padding-кольца (дилатация маски на `PaddingCells`) — padding проверяет только `!Occupied` (растения рядом не мешают; padding-клетка в залоченном/несуществующем чанке считается свободной). Padding-клетки занятыми НЕ помечаются.
- Поворот маски — вокруг её **центра** (bounding-box), а не якорной клетки: при вращении призрак не «уезжает» от курсора.
- `Place`/`Remove`/`RestorePlace`: помечают/освобождают `Occupied` только по клеткам маски. Спавн префаба — в центре bounding-box маски (Y=0), поворот `rotationY`.
- `PlacedObject` дополняется `RotationSteps` (int 0..3) для Step90-масок; `RotationY` остаётся для визуала.
- **Free5-поворот вращает футпринт**: при произвольном угле занятые клетки вычисляются консервативной растеризацией повёрнутого футпринта (клетка занята, если повёрнутый прямоугольник/маска её перекрывает). Для Step90 — быстрый путь через предвычисленные повороты маски.
- Новое поле `PlacedObject.OccupiedCells: List<(Vector2Int chunkCoord, int cellX, int cellY)>` — занятые клетки фиксируются при установке (а не выводятся повторной растеризацией при удалении — защита от дрейфа float). На него же опираются `Remove`, `TryGetAt` и бульдозер. Кросс-чанковая адресация — через существующий механизм `ChunkSystem` (`ResolveCell`/`WorldToCell`).
- Поиск здания по клику/бульдозеру: `IPlacementService.TryGetAt(Vector3 worldPos, out PlacedObject)` — линейный поиск по `PlacedObjects` с проверкой попадания клетки в маску (объектов мало, YAGNI на словарь). `BulldozeTool.TryRemovePlacedObject` переводится на него (вместо дистанции до центра).

### A4. Превью

- `PlacementTool.SnapPosition`: единый клеточный снап (чанковый branch удаляется). Призрак ставится в центр bounding-box маски.
- `AdjustRotation` при Step90 инкрементирует `RotationSteps` (маска и призрак вращаются согласованно).
- `BrushPreviewService.RenderFootprint` заменяется на `RenderFootprintCells(IReadOnlyList<(Vector3 pos, bool ok)>)`: инстансированные квады клеток маски, **каждая клетка зелёная/красная по собственной валидности** (два инстанс-дропа: валидные и невалидные). `PlacementService` отдаёт пер-клеточную валидность методом `EvaluateFootprint(data, worldPos, rotationSteps, List<(Vector3, bool)> результат)` — превью и `CanPlace` используют одну и ту же проверку (принцип «превью не врёт», как у кисти).
- Общая валидность (тинт призрака + цвет контура) = все клетки ok, **включая padding**. Блокирующие padding-клетки попадают в выдачу `EvaluateFootprint` с ok=false и рисуются красным (игрок видит, что мешает сосед); свободный padding не рисуется вовсе.

### A4b. Снос деревьев (после A3)

- `ITreePlacementService.Remove(PlacedTree)` и `PlacedTrees` **уже публичны** — новых членов контракта не нужно, нужна только обвязка.
- `BulldozeTool.TryRemovePlacedObject` расширяется: сначала здания/декор (`TryGetAt` из A3), затем деревья (попадание по клеткам ствола из `PlacedTrees`). Снос → `Remove` + возврат `PlantData.SeedCost / 2` в кошелёк (SeedCost всегда определён; 0 → возврат 0, без особых случаев).
- Превью: при наведении бульдозера дерево, которое будет снесено, подсвечивается красным (MPB-тинт на рендерерах визуала дерева); снятие наведения возвращает вид.

### A5. Сейв (ломаем формат)

- `FarmSaveData.PlacedObjectData`: + `RotationSteps`. Важно про имена: удаляется enum `PlacementLevel` из `PlaceableData`; поле `PlacedObject.Level`/`PlacedObjectSaveData.Level` — это **уровень прокачки здания**, оно ОСТАЁТСЯ.
- `ProductionSlotSaveData` сейчас мэтчится по `PlaceableId + ChunkCoord` — после перехода на клетки два одинаковых здания могут жить в одном чанке. В мэтчинг добавляются `CellX/CellY`.
- `FarmSaveData.Version` (есть, =1) повышается до 2; проверка версии — новый код в загрузке (сейчас `Version` никем не читается): `Version < 2` → лог + новая игра.
- Существующие ассеты `Placeable_*.asset` обновляются: `GridSize` переводится из чанков в клетки (1 чанк = 8 клеток; Mill 1×1 чанк → маска ~6×6–8×8 по видимому размеру префаба), `Level` удаляется. Первичные маски ставим по bounding-box рендереров префаба (скриптом), владелец потом правит в новом редакторе.

### A6. Тесты (EditMode)

- `FootprintMask`: парсинг, поворот ×4, fallback на GridSize, рваные строки.
- `PlacementService.EvaluateFootprint`/`CanPlace`: маска L-формы на чистом поле; клетка занята → именно она невалидна; пересечение границы чанка; залоченный чанк; padding=1 не даёт поставить вплотную, но не помечает клетки.
- Паритет: `EvaluateFootprint` все-ok ⇔ `CanPlace` true.

## Часть B: текстуры и нормали земли/дорожек

### B1. Текстуры

- `Texture2DArray` × 2: `_GroundAlbedoArray`, `_GroundNormalArray`; слайс на каждый `GroundState` (7: Grass, Tilled, Watered, Fertilized, PathStone, PathWood, PathBrick). Старый 2×2 атлас выводится из употребления.
- Эдитор-утилита `GroundTextureArrayBuilder` (меню WheatFarm/Build Ground Texture Arrays): собирает массивы из списка исходных текстур в новом `GroundTextureSet` (ScriptableObject: пары albedo+normal на состояние), сохраняет ассеты, назначает в `GroundMaterial`.
- Плейсхолдеры: процедурный генератор (эдитор-скрипт) — камень (вороной/трещины), доски (полосы + волокно), кирпич (кладка со смещением); albedo + высота → нормали (Sobel). 512×512, tileable. Заменяются художественными без изменения кода.

### B2. Шейдер `GroundInstanced`

- Семплинг: слайс по `groundState`. UV: состояния 0–3 — текущий локальный UV клетки; дорожки 4–6 — **мировая проекция** `worldPos.xz / _PathTileSize` (бесшовность между клетками).
- Нормали: TBN фиксированный (T=(1,0,0), B=(0,0,1), N=(0,1,0)) — земля плоская. Освещение: NdotL по возмущённой нормали + лёгкий Blinn-Phong спекуляр только для дорожек (`_PathSpecular`, `_PathSmoothness`).
- Кромки дорожек: доделать заготовку `neighborFlags` (биты N/E/S/W/NE/SE/SW/NW уже считаются в `UpdateGroundNeighborFlags`): для путевых клеток — скругление углов (`_CornerRadius`) там, где нет соседей-дорожек, и смягчение кромки (`_EdgeSoftness`) к траве; в «вырезанных» местах фрагмент рисует подложку (slice травы).
- **Бленд на стыке разных типов дорожек**: свободного канала в `MeshProperties` НЕТ (все 12 float'ов `color/uv/cropState` заняты, `uv.w` уже двухцелевой). Решение: **расширяем структуру** новым полем `uint neighborTypes` (4 ниббла N/E/S/W, заполняется в `UpdateGroundNeighborFlags`). Это синхронное изменение в: `MeshProperties.cs` (`Size()`), `GetStructedBuffer.hlsl` (HLSL-зеркало структуры), местах аллокации GPU-буферов (stride), геттерах (`GetUV_float` и др.) — план обязан перечислить все точки касания. На путевой клетке, граничащей с дорожкой другого типа, в полосе ~полклетки текстуры двух slice'ов смешиваются smoothstep-ом. Стыки трёх+ типов в одном углу не вылизываем (берётся сосед по доминирующему направлению).
- Тинты `_TintPath*` остаются множителями (питают и превью кисти — без изменений API).

### B3. Проверка

- Шейдерные изменения — визуально через Unity MCP скриншоты: бесшовность дорожки на 4+ клетках, скругление кромок на углах/изгибах, нормали читаются при дневном освещении (DayNight).
- EditMode-тест на `GroundTextureSet`/билдер: массив собирается, размерности/формат корректны, слайсы по индексам состояний.

## Часть C: пикер цвета краски

- При активном инструменте краски в HUD показывается палитра из ~8 предустановленных цветов (маленькая панель в стиле существующего `PanelBuilder`/HUD). Клик → `DyeTool.SelectColor(color)`. Превью кисти подхватывает цвет автоматически (уже подключено через `PreviewCellColor`).
- Выбранный цвет сохраняется на время сессии (в сейв не пишем).

## Вне объёма

- Сплайновые дороги.
- Специальные тайлы-переходы между типами дорожек (делаем мягкий бленд, см. B2).
- Миграция старых сейвов.
- Топор/древесина как ресурсная механика (снос деревьев — это именно снос).
