# Система превью для инструментов размещения

Дата: 2026-06-11
Статус: согласован с владельцем проекта

## Цель

Игрок всегда видит, что произойдёт до клика:

1. При установке объекта — полупрозрачный «призрак» с текстурами оригинала и индикацией валидности (зелёный/красный).
2. При рисовании дорог — размер кисти и превью будущего вида дороги на земле.
3. Превью видно сквозь перекрывающие объекты: перекрытая часть рисуется подсвеченной заливкой-силуэтом, кромка силуэта обрамлена анимированным пунктиром («бегущие муравьи»).

## Текущее состояние (что уже есть)

- `PlacementTool` ([Assets/Scripts/Player/Tools/PlacementTool.cs](../../../Assets/Scripts/Player/Tools/PlacementTool.cs)) — призрак есть, но примитивный: все материалы подменяются одним прозрачным URP Lit (объект превращается в плоское пятно без текстур), сквозь препятствия не виден. Снап к клеткам/чанкам и поворот колесом уже работают.
- Дороги — состояние клеток (`GroundState.PathStone/Wood/Brick`), рисуются кистью через `BrushService`; превью кисти нет вообще.
- Земля — GPU-инстансинг (`GroundInstanced.shader`), состояние клетки в `cropState.z` пер-инстансного буфера, тинты дорожек — свойства материала (`_TintPathStone` и т.д.).
- Два URP-рендерера: `PC_Renderer` и `Mobile_Renderer` (Assets/Project/Settings).

## Принятые решения

| Вопрос | Решение |
|---|---|
| Рентген + пунктир | Двухпроходный шейдер призрака + ScriptableRenderFeature для контура (вариант A) |
| Превью кисти | Подсветка реально изменяемых клеток + кольцо радиуса |
| Охват | Единая система превью кисти для всех кистевых инструментов |
| Валидность | Зелёный/красный тинт призрака и цвет пунктира |

## Архитектура

### 1. `GhostPreview.shader` (Assets/Project/Shaders)

Два прохода, очередь Transparent, `ZWrite Off`, теней не кастует:

- **Проход «видимая часть»** (`ZTest LEqual`): полупрозрачный, семплирует `_BaseMap` оригинала, умножает на тинт валидности. Призрак выглядит как сам объект, а не как цветное пятно.
- **Проход «перекрытая часть»** (`ZTest Greater`): ровная полупрозрачная заливка цветом валидности — силуэт виден сквозь любые объекты. Этот проход — самодостаточный fallback: на Mobile, где render feature выключена, рентген-заливка всё равно работает (без пунктира).

Фабрика гост-материалов: для каждого исходного материала рендерера создаётся материал `GhostPreview` с копией `_BaseMap`/`_BaseColor`. Материалы кэшируются по исходному материалу, тинт меняется через `MaterialPropertyBlock` (без пересоздания материалов при смене валидности).

### 2. `GhostOutlineRenderFeature` (только PC_Renderer)

ScriptableRenderFeature + RenderGraph-проход (URP 17):

1. Рендерит рендереры слоя `PlacementPreview` override-материалом в маску R8 с `ZTest Greater` против глубины сцены — в маске оказывается только перекрытая часть превью.
2. Фуллскрин-композит: по краю маски — контур по силуэту (расширение маски минус маска), модулированный анимированной диагональной полосатой маской → визуально пунктир, бегущий по кромке; внутри маски — мягкая дополнительная подсветка.
3. Цвет контура и заливки берётся из глобального шейдер-вектора `_PreviewHighlightColor`, который выставляет `PlacementGhostService` по валидности.

Осознанное упрощение: пунктир — это экранные полосы поверх контура («marching ants»), штрихи не параметризованы вдоль кромки геометрически. Принято как достаточное.

Настройки фичи: толщина контура, плотность/скорость пунктира, сила внутренней подсветки.

### 3. `PlacementGhostService`

Рендер-логика призрака выносится из `PlacementTool` в сервис (регистрация в `FarmScope`):

```
IPlacementGhostService:
    Show(PlaceableData data)
    UpdatePose(Vector3 position, float rotationY)
    SetValid(bool valid)
    Hide()
```

Обязанности: инстанс призрака без коллайдеров и MonoBehaviour-ов, слой `PlacementPreview`, гост-материалы через фабрику, отключение теней, установка `_PreviewHighlightColor`. `PlacementTool` оставляет себе снап, поворот и `CanPlace`, вызывая сервис.

### 4. `BrushPreviewService`

Единое превью для кистевых инструментов (дороги, посадка, полив, удобрение, краска, бульдозер):

```
IBrushPreviewService:
    Show(IBrushPreviewSource source)   // источник: цвет клетки + фильтр применимости
    UpdateAt(Vector3 worldPos)
    Hide()
```

- Перечисление клеток выносится из `BrushService.ApplyAtWorldPos` в общий метод (`GetAffectableCells`), чтобы превью и применение использовали один и тот же код — превью не врёт.
- **Распределение фильтров:** `GetAffectableCells` фильтрует только по `Unlocked`-чанкам. Проверка `Occupied` (сейчас зашита в `ApplyAtWorldPos`) переезжает в пер-инструментные фильтры с точными предикатами:
  - посадка: `!Occupied && !HasPlant`;
  - дороги: `!HasPlant && (!Occupied || GroundState >= PathStone) && GroundState != выбранный тип дорожки` — свободные клетки плюс перекраска существующей дорожки другим типом; клетки, занятые зданиями/деревьями, и клетки с уже таким же типом дорожки пропускаются;
  - бульдозер: `GroundState >= PathStone || HasPlant` — дорожки и растения. Деревья кистевой бульдозер не трогает; механизма сноса деревьев в игре сейчас нет вообще (ничто не вызывает `TreePlacementService.Remove`, у визуала деревьев нет коллайдеров) — снос деревьев вне объёма этой спеки;
  - серп: `HasPlant && IsHarvestable`;
  - выкорчёвка: `HasPlant`;
  - полив/удобрение/краска: `HasPlant`.

  Это попутно чинит существующий скрытый баг: дорожки ставят `Occupied = true`, поэтому сейчас бульдозер и перекраска дорожки другим типом через кисть не достигают своих клеток вовсе (а снос растений кистью работает лишь потому, что посадка `Occupied` не выставляет).
- Инструмент-источник дополняет фильтр своей логикой (например, дорога не красится поверх растений) и задаёт цвет: для дорожек — тинт из материала `GroundInstanced` (игрок видит будущий вид дороги), для полива — синий и т.д.
- Рендер: `Graphics.RenderMeshInstanced` квадов чуть выше земли (y ≈ 0.02) полупрозрачным цветом + тонкое кольцо радиуса кисти (квад с ring-шейдером по `BrushService.WorldRadius`).
- Квады и кольцо — в слое `PlacementPreview`, поэтому превью дороги за зданием показывается тем же силуэтом с пунктиром.

### 5. Поток данных

```
FarmInteractionController (Update, raycast в Y=0)
    → PlacementTool.UpdatePreview(pos)        → PlacementGhostService
    → кистевой инструмент / BrushPreview hook → BrushPreviewService
Валидность: PlacementService.CanPlace → SetValid → тинт + _PreviewHighlightColor
```

Превью скрывается, когда курсор над UI (`EventSystem.IsPointerOverGameObject`), при смене инструмента и при `ClearSelection`.

Сейчас `FarmInteractionController.HandlePlacementPreview` вызывает превью только для `ToolId.Placement` — диспетчеризация обобщается: контроллер каждый кадр отдаёт позицию курсора активному инструменту, если тот предоставляет источник превью (один хук вместо отдельной обвязки в каждом инструменте).

У превью-объектов нет и не должно появляться коллайдеров (призрак их лишается при создании, квады кисти — `RenderMeshInstanced`); исключение слоя из рейкастов — защитная мера, а не приглашение добавить коллайдеры.

## Сопутствующие проблемы, закрываемые этой архитектурой

- **Футпринт зданий**: подсветка занимаемых клеток/чанков на земле тем же квад-рендерером (зелёный/красный по валидности).
- **Bulldoze**: красная подсветка сносимых клеток — тот же `BrushPreviewService` с бульдозерным фильтром (`GroundState >= PathStone || HasPlant`, см. распределение фильтров выше).
- **Производительность**: кэш гост-материалов, `MaterialPropertyBlock`, инстансинг квадов, ноль аллокаций в Update после создания призрака.
- **Слой `PlacementPreview`**: добавляется в проект; исключается из физических рейкастов.

## Вне объёма

- Геометрическая параметризация пунктира вдоль контура.
- Превью для Mobile_Renderer с пунктиром (там работает fallback-заливка).
- Изменение правил размещения/валидности (используются существующие `CanPlace` и фильтры кисти).

## Тестирование

- EditMode-тест: множество клеток, возвращаемое превью, совпадает с множеством клеток, которое реально изменит кисть (общий метод перечисления).
- EditMode-тест: фабрика гост-материалов копирует `_BaseMap`/`_BaseColor` и кэширует по исходному материалу.
- Визуальная проверка через Unity MCP скриншоты: призрак частично за мельницей → видимая часть с текстурами, перекрытая — заливка с пунктирной кромкой; кисть дорожки у здания → подсветка клеток и кольцо, валидность красная на занятых клетках.
